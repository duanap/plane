# Plane V1.1 UX Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Upgrade Plane V1 with a three-mode home, unified drag placement, per-game destroyed-outline setting, clearer attack marks, and a privacy-safe local two-player result/handoff flow.

**Architecture:** Keep the existing game engine and three browser modes. Add small shared pure modules for placement manipulation and local-flow transitions; extend game/room state with one immutable game option; update each browser client to consume the shared behavior. Online remains server-authoritative and sanitizes reveal-disabled state.

**Tech Stack:** TypeScript 5.8.3, browser Pointer Events, Node.js 22, existing Node HTTP/SSE server, Docker.

**Spec:** `docs/superpowers/specs/2026-09-11-v1.1-ux-design.md`

## Global Constraints

- Core board remains 10x10 with exactly three legal non-overlapping planes per player.
- `revealDestroyedPlane` is one shared immutable per-game rule.
- Online clients never receive hidden opponent plane cells while the game is in progress.
- Final game results reveal both complete fleets.
- No new runtime dependencies.
