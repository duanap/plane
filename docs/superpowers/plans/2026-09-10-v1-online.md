# Plane V1 Online Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a real two-device online room flow with authoritative hidden state, real-time updates, reconnect, and rematch while preserving the tested V1 game rules.

**Architecture:** Keep `src/game/*` unchanged as the rule engine. Add a transport-independent `RoomStore` for room lifecycle/public views, expose it through the existing zero-dependency Node HTTP server with JSON commands + SSE, and add a separate online browser entry that reuses geometry helpers for placement.

**Tech Stack:** Node.js 22+, TypeScript 5.8+, built-in `node:test`, built-in HTTP server, Server-Sent Events, native browser ES modules.

**Spec:** `docs/superpowers/specs/2026-09-10-v1-online-design.md`

## Global Constraints

- Board size remains exactly 10 x 10 and each player submits exactly 3 legal planes.
- `src/game/*` remains the source of truth for attacks and geometry.
- Undestroyed opponent plane positions/directions must never appear in a player-facing room view.
- Every room mutation requires a valid player token.
- V1 room state is memory-only and expires after 6 hours of inactivity.
- Real-time updates use SSE with JSON POST commands and add no runtime dependencies.
- Existing local hot-seat page remains playable.
