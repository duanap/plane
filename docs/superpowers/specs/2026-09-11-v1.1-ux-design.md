# Plane V1.1 UX Design

## Scope

V1.1 improves the existing three-mode Plane game without changing the 10x10 / 3-plane / hit-head-to-destroy core rules.

## Home

`/` becomes a mode selector instead of launching local play directly. It shows three primary cards:

- 本地双人 -> `/local.html`
- 在线对战 -> `/online.html`
- AI 练习 -> `/ai.html`

`/local.html` hosts the existing local game client.

## Unified placement interaction

All three modes use the same placement behavior:

- Placement starts with three automatically generated legal planes already on the board.
- A player can press/touch any occupied plane cell and drag the whole plane.
- The grabbed cell keeps its relative offset to the plane head while dragging.
- During drag, the candidate whole-plane footprint is previewed.
- Legal preview uses the normal selected/highlight state.
- Out-of-bounds or overlapping preview is visibly invalid/red.
- Releasing on a legal position commits the move; releasing on an illegal position restores the previous position.
- Clicking/tapping a plane selects it; the rotate action rotates the selected plane 90 degrees clockwise if that rotated placement is legal.
- An illegal rotation is rejected and keeps the old orientation.
- Random placement remains available and re-generates all three legal planes.
- Ready/Start is enabled only for a legal 3-plane fleet.

## Per-game destroyed-outline option

Each game has one shared option:

`revealDestroyedPlane: boolean`

Meaning:

- `true`: when a head is hit, the destroyed plane's complete 10-cell footprint becomes visible to the attacker.
- `false`: only the destroyed-head marker and already-known attack marks remain visible during play; the remaining hidden body cells are not revealed.
- At final game end, both complete fleets are still revealed regardless of this option.

Mode ownership:

- Local: selected before Player A placement and applies to both players.
- Online: selected by Player A when creating the room; Player B can view but cannot change it.
- AI: selected together with difficulty before placement.
- The option cannot change after the game starts. Online rematches keep the room option.

The server remains authoritative in online mode. When the option is disabled it must not include destroyed-plane body cells in public attack payloads or opponent revealed-plane state until `FINISHED`.

## Battle marks

The visual language is shared across local, online and AI modes:

- MISS: clear hollow ring, low-emphasis blue/gray.
- HIT body: bold cross, amber/orange with stronger contrast.
- DESTROYED head: explosion/burst mark, red, with a short one-shot emphasis animation.

Marks use both shape and color. The destroyed-head marker remains visible whether or not full-plane reveal is enabled.

## Local two-player flow

Local play is privacy-safe and result-readable:

1. Open `/local.html`.
2. Choose the destroyed-outline rule.
3. Player A adjusts the pre-generated three-plane layout and confirms.
4. Privacy handoff screen asks for Player B.
5. Player B adjusts the pre-generated layout and confirms.
6. Privacy handoff screen announces battle start; first player is randomized.
7. Current player opens their turn.
8. Player selects one enemy coordinate and explicitly confirms attack.
9. Attack result stays on screen for the current player. No automatic handoff occurs.
10. Current player presses `结束回合`.
11. Full-screen privacy handoff asks for the next player, who presses `开始我的回合` before seeing their board.
12. Repeat until one player destroys all three opponent heads.
13. Final screen reveals both fleets, result stats and rematch action.

The local battle screen provides enemy/own board tabs. Enemy is the default tab at the start of a turn. The own board is view-only.

## Non-goals

V1.1 does not add accounts, persistence, rankings, chat, matchmaking, Redis, multi-instance online state or new game rules.

## Verification

Required gates:

- Unit tests for drag candidate math, illegal drag rejection and legal rotation.
- Game/room tests for reveal on/off behavior and final reveal.
- Local-flow tests for explicit result stage and end-turn handoff.
- Existing online hidden-information tests remain passing.
- TypeScript build passes.
- Static smoke covers `/`, `/local.html`, `/online.html`, `/ai.html` and compiled module dependency routes.
- Docker image build and runtime smoke pass.
